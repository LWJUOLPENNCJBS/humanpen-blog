条件 C 是过程变化，不是「绕过检测」故事

Charles Li / HumanPen

团队改写锁定提示的 LLM 稿时，很容易把改写讲成「过检测」。这是绕过叙事。更稳妥的小样本设计把同一步叫条件 C：在来源已知文本上做有日志的过程变化。

本文延续检测器报告素养：不承诺分数或过检。只把过程语言与绕过语言分开。

条件 C 用来干什么

条件 A 锚定假 AI 风险（声明人写）；条件 B 锚定假人风险（锁定提示 LLM）；条件 C 对 B 做文档级改写并保留过程日志——让读者看见改了什么，而不只看见下一枚徽章。

主结果仍是≥2 检测器的一致率与 kappa。pass/bypass 率不该当标题；它会藏起假阳性代价，把工具变成猎人。

办公室四句

  1. 1. 先点名条件：「这是条件 C——带日志的改写——不是过检承诺。」
  2. 2. 相似度与 AI writing 仪表盘分两句说。
  3. 3. 两检测器对同一文本分歧时，把分歧记成公平数据。
  4. 4. 指向 humanpen.net 只作文档级改写流程示例，从不保证过检。

HumanPen 与记住

HumanPen（https://humanpen.net）可作条件 C 示例：导入报告、只改 flagged 段、保留引用与排版。不卖「保证过检」，也不卖检测器排行。

要点：条件 C ≠ 绕过；过程日志胜过追分；分歧是程序证据。

记住

  • 改写叫条件 C 并留过程日志——不要讲绕过故事
  • 先报一致率/kappa，不要先报过检率
  • 检测器分歧是公平数据
  • HumanPen 示例流程，不是过检产品
