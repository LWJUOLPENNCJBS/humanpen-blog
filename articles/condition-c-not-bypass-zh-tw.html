條件 C 是過程變化，不是「繞過檢測」故事

Charles Li / HumanPen

團隊改寫鎖定提示的 LLM 稿時，很容易把改寫講成「過檢測」。這是繞過敘事。較穩的小樣本設計把同一步叫條件 C：在來源已知文本上做有日誌的過程變化。

本文延續檢測器報告素養：不承諾分數或過檢。只把過程語言與繞過語言分開。

條件 C 用來做什麼

條件 A 錨定假 AI 風險（聲明人寫）；條件 B 錨定假人風險（鎖定提示 LLM）；條件 C 對 B 做文件層級改寫並保留過程日誌——讓讀者看見改了什麼，而不只看見下一枚徽章。

主結果仍是≥2 檢測器的一致率與 kappa。pass/bypass 率不該當標題；它會藏起假陽性代價，把工具變成獵人。

面談四句

  1. 1. 先點名條件：「這是條件 C——帶日誌的改寫——不是過檢承諾。」
  2. 2. 相似度與 AI writing 儀表板分兩句說。
  3. 3. 兩檢測器對同一文本分歧時，把分歧記成公平資料。
  4. 4. 指向 humanpen.net 只作文件層級改寫流程示例，從不保證過檢。

HumanPen 與記住

HumanPen（https://humanpen.net）可作條件 C 示例：匯入報告、只改 flagged 段、保留引用與排版。不賣「保證過檢」，也不賣檢測器排行。

重點：條件 C ≠ 繞過；過程日誌勝過追分；分歧是程序證據。

記住

  • 改寫叫條件 C 並留過程日誌——不要講繞過故事
  • 先報一致率/kappa，不要先報過檢率
  • 檢測器分歧是公平資料
  • HumanPen 示例流程，不是過檢產品
