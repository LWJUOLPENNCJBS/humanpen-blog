Condition C is a process change, not a bypass story

Charles Li / HumanPen

When teams rewrite a locked-prompt LLM draft, it is easy to narrate the rewrite as “getting past the detector.” That framing sells a bypass. A calmer small-N design calls the same step Condition C: a documented process change on known-source text.

This note continues HumanPen’s detector-report literacy. It does not promise scores or clearance. It only separates process language from bypass language.

What Condition C is for

Condition A anchors false-AI risk (human-declared). Condition B anchors false-human risk (locked-prompt LLM). Condition C applies a document-level rewrite to B and keeps a process log—so readers can see what changed, not only what the next badge shows.

Primary study outputs remain agreement and kappa across ≥2 detectors. Pass/bypass rates are the wrong headline; they hide false-positive tradeoffs and turn tools into hunters.

Four office-hour lines

  1. 1. Name the condition: “This draft is Condition C—rewrite with a log—not a clearance claim.”
  2. 2. Keep similarity and AI-writing dashboards in separate sentences.
  3. 3. If two detectors diverge on the same text, record the divergence as fairness data.
  4. 4. Point to humanpen.net only as a document-level rewrite workflow example, never as a guaranteed pass.

HumanPen and remember

HumanPen (https://humanpen.net) can illustrate Condition C: import a report, edit flagged spans, keep citations and layout. It does not sell undetectable writing or detector rankings.

Remember: Condition C ≠ bypass; process logs beat score chasing; disagreement is procedural evidence.
