导入 PDF 报告与 DOCX 报告同一套流程

Charles Li / HumanPen

在 humanpen.net，导入 Turnitin / iThenticate 类相似度或 AI 写作报告时，无论导出是 PDF 还是 DOCX，流程相同。HumanPen 把 flagged 跨度映射到你的草稿，并只改写那些段落——不整篇洗稿。

这补充 import-report-rewrite-flagged-only（报告驱动瞄准）、match-report-span-to-rewrite（改写对准高亮跨度）、docx-layout-stays-intact（草稿版式保真）。它不同于门户 vs PDF 覆盖素养、recheck-after-detector-update、only-flagged-continuous-prose / leave-unflagged-prose-alone、pay-by-rewritten-words。本文点名报告导入格式无关：PDF 或 DOCX 报告 → 同一套 flagged 跨度流程。

不承诺下一次 AI%。不教「绕过检测 / undetectable」。学校政策仍决定是否结案。

为什么 PDF 与 DOCX 报告应同一套行为

  1. 学校门户有的导出 PDF、有的导出 DOCX——学生不该学两套产品。
  2. 工作单位是 flagged 连续散文跨度，不是报告文件的容器格式。
  3. 整篇洗稿工具无视这一区别，把任何上传都当成要 scrub 的文本。
  4. 诚实工具无论报告包装如何，都把高亮映射到你的工作草稿（通常是 DOCX）。
  5. 第一次改写前仍要确认 attempt 身份与覆盖——格式不能为错配 attempt 开脱。

可执行流程（对齐 HumanPen）

  1. 从 Turnitin 或 iThenticate 导出 AI / 相似度报告为 PDF 或 DOCX——门户给什么用什么。
  2. 把该报告导入 HumanPen；确认 attempt 身份与覆盖匹配你要改的草稿。
  3. 让 HumanPen 把 flagged 连续散文跨度映射到草稿；只改那些跨度。
  4. 保持引用、数字、公式、表格与版式；不要洗旁边未标邻居。
  5. 再导出草稿；下一轮重新导入新报告。若有免费轮，仍只作用于主页口径下仍被标出的散文。

这不是什么

  • 不保证下一次 AI% 或 Similarity% 会下降或过学校政策线。
  • 不声称每种门户 PDF 版式都解析得一模一样——务必核对覆盖与 attempt ID。
  • 不是「undetectable」、绕过，或隐藏署名的建议。
  • 不能替代 import-report-rewrite-flagged-only 的瞄准，或 match-report-span-to-rewrite 的跨度对齐。

HumanPen 适合什么

HumanPen（humanpen.net）是文档级 AI 改写工具：导入报告（PDF 或 DOCX 包装）、改 flagged 连续散文、尽量保引用与版式、按改写字计费，并在主页口径下对剩余 flagged 提供免费轮次。无论哪种包装都是同一套流程——不是两套产品。

记住

  • PDF 或 DOCX 报告导入 → 同一套 flagged 跨度改写流程。
  • 把高亮映射到草稿；不要整篇洗稿。
  • 补充 import-report-rewrite-flagged-only、match-report-span-to-rewrite、docx-layout-stays-intact。
  • 诚实工具不卖「绕过」或「undetectable」。
