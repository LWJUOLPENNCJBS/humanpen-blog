Label the source before you argue the score

Charles Li / HumanPen

Office-hour fights often start with a number: “The badge says 47%.” A calmer protocol starts one step earlier: what is the known source of this text—human-declared, locked-prompt LLM, or a logged rewrite?

This note continues detector-report literacy. It does not promise scores. It only puts known-source labeling ahead of score arguments.

Why source first

Without a source label, a high flag on human-declared prose and a high flag on raw LLM prose look identical in a screenshot. They are not the same risk story. Condition A/B/C makes that difference teachable on a mini-set.

Agreement and kappa across ≥2 detectors still beat catch-rate headlines. Source labels make disagreement interpretable instead of personal.

Four steps

  1. 1. Write the source condition on the draft before opening the portal card.
  2. 2. Keep similarity and AI-writing dashboards in separate sentences.
  3. 3. If detectors diverge, log the divergence next to the source label.
  4. 4. Treat rewrite as Condition C process change—not as proof the next card will clear.

HumanPen and remember

HumanPen (https://humanpen.net) can show Condition C: import a report, edit flagged spans, keep citations/layout. It does not sell clearance or rankings.

Remember: known source before score; kappa before catch-rate; process over denial.

Remember

  • Name A/B/C before debating the badge
  • Known source makes false-positive risk visible
  • Disagreement + source label = fairness data
  • HumanPen exemplifies Condition C workflow, not a pass
