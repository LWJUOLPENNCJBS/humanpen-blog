Cohen’s kappa 不是「抓獲率」：小樣本檢測研究裡，先問工具多常達成一致

Charles Li / HumanPen

校園討論常問：哪個 AI 寫作檢測器「抓得更多」？這把工具當成獵人。較穩的小樣本協議問另一件事：同一批有標籤文本上，兩個檢測器多常一致——Cohen’s kappa 是多少？

本文延續檢測器報告素養：不承諾分數、排行或任何「保證過檢」。只說明為何面談裡，一致率比抓獲率更公平。

kappa 在回答什麼

一致率是兩邊落在同一閾值側的文本占比；kappa 再校正偶然一致。兩者都不是作者身分判決，只描述固定集合上評分者的concordance。

對條件 A（聲明人寫）文本旗標更多的工具，不等於「更嚴更好」——可能抬高假陽性。沒有來源已知設計的抓獲率，會把這種代價藏起來。

可重用的小-N 草圖

來源已知：條件 A 人寫聲明、條件 B 鎖定提示的純 LLM、條件 C 對 B 做帶過程日誌的文件層級改寫。條件間主題／體裁匹配。≥2 檢測器當評分者。揭露提示、模型、設定與隸屬關係。

主結果：一致率 + kappa。不要用 pass/bypass 率開場。工具分歧時，把分歧當成程序公平信號——至少有一個評分者在該條上錯了。

談話前四步

  1. 1. 把研究問題寫成「一致」，而不是「誰抓得多」。
  2. 2. 表格列出每條文本的來源條件與兩邊檢測輸出。
  3. 3. 算一致率與 kappa；用白話記下分歧。
  4. 4. 若改寫入場，只作條件 C 過程變化——不是下一張入口卡片會清零的證據。

HumanPen 與記住

HumanPen（https://humanpen.net）可作條件 C 文件層級改寫示例（匯入報告、只改 flagged 段、保留引用與排版）。它不賣檢測器排行，也不賣保證過檢。

重點：kappa ≠ 抓獲率；小樣本也能練團隊判讀；分歧是公平資料。
