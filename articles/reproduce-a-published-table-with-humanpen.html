Reproduce a published table from PDF to rerun you can audit with HumanPen

A published table is a claim that somebody else's numbers can be checked. Reproducing it is one of the most useful exercises in research, and one of the most tedious: find the source data, infer the analysis, match the formatting, then write down where yours differs. This page describes that as a pipeline and shows where HumanPen Start Project fits, using the product's own worked example as the model.

The example is an IST secondary analysis. The public page states a full analysis set of nineteen thousand four hundred thirty-five patients, a primary endpoint of death or dependency at six months, and about one hundred fifty missing outcomes handled with a sensitivity analysis. It shows an aspirin group at sixty-two point two percent and a control group at sixty-three point five percent, with a P value of zero point zero seven two. That level of detail is what makes a reproduction checkable.

The pipeline is shaped by the product's own use case. Start Project lists "reproducing published results" as a use case: it reruns a paper's regressions and figures, with notes on differences. The review example adds what the check covers — a primary endpoint that matches, analysis populations that add up, a clean rerun that reproduces the results exactly, and every reference found one by one.

Stage one: write the question the paper answered

Before touching data, write one sentence naming the population, the endpoint and the timepoint. The public example does this: a full analysis set, death or dependency at six months, with missing outcomes handled separately. A reproduction that skips this step drifts into computing whatever the columns allow, and the resulting table can be correct in arithmetic and wrong as an answer.

Capture the pre-specified contrasts and the missing-data rule in the same note. If the paper states that about one hundred fifty missing outcomes receive a sensitivity analysis, that is a decision to reproduce, not a rounding detail. In the example the primary comparison is reported with an odds ratio and a confidence interval and a P value, and the review states that the endpoint matches across groups. Those are the numbers your rerun must land on.

Stage two: prepare the data and the dictionary

HumanPen's research projects accept Excel, CSV, Word, PDF and zip files up to five gigabytes in total. Wind and CNKI data should be exported first. If the published study used a statistical package, note that analyses originally done in SPSS or Stata are performed using Python or R — so the reproduction will be a reimplementation in one of those languages, not a replay in the original package.

Write a data dictionary as you go: which column is the endpoint, how missing values are coded, which variables define the analysis set. The dictionary is what makes the rerun auditable by someone else. It is also what lets you explain a difference later: if your number disagrees, the first place to look is a definition, not a random seed.

Stage three: get a plan before the run

Start Project is explicit about the order: describe the task and attach files, the system confirms requirements and proposes a plan, and work starts only after your approval. After a check by a second system, reports, charts and code are delivered. Read the plan against your one-sentence question. If the plan computes a different estimand, correct it before approval — changing it afterwards is a new round, not a correction.

For an API-driven reproduction, the developer page describes the same shape. A project moves through states, and while it waits for input the required-input field says what to do next. Confirm the plan by naming the version you were shown. That version discipline matters in a reproduction, where a later reader needs to know which plan produced which table.

Stage four: rerun and write the difference note

A reproduction is not a pass/fail test. Small differences are expected when a rule is described in prose rather than code. The public example is unusually clear about this: a clean rerun reproduces the results exactly, and a separate comparison report with notes on differences is part of the deliverable. Aim to match, and write down every place you cannot.

The note should say what you changed, why, and how much the result moved. If you had to choose a different coding for a missing category, state it. If you used Python where the paper used Stata, say so. A reader who can follow the difference is served better by an honest mismatch than by a suspiciously perfect match.

Revisions follow the project path: request the change in the project, see the scope explained before work starts, confirm, and receive a new version while past versions are kept. Do not patch the code in a separate file and lose the link between plan and result.

Stage five: format for a reader, not a screen

A reproduction is easier to trust when it looks like the paper. HumanPen's research page describes journal-grade figures at three hundred dpi and three-line tables with captions to standard. The documented use cases also list R or Python code alongside a Word report, and a comparison report with figures and code for reproduced results.

Keep the code with the document. A table without code is an assertion; a table with code is an invitation to check. The isolated sandbox described on the page encrypts data in transit, never shares a project across users or uses it for training, and allows deletion at any time. That is relevant when the source data is licensed or sensitive.

Stage six: verify the scholarship

Check the reference list the way the review example does: every reference found, one by one. Then confirm that the sentences around your table cite the sources that actually support them. HumanPen's document tools keep citations, numbers and claim strength unchanged during a wording pass, which is what you want when the table is the point of the document.

Projects are kept for six months after the last activity, with a reminder three days before expiry, and can be deleted at any time. Export the report, code, figures and comparison note into your own repository after the reproduction is accepted.

Frequently asked questions

Can HumanPen replay an analysis in the original statistical package?

No. Analyses originally done in SPSS or Stata are performed using Python or R. A reproduction is a reimplementation in one of those languages, with code delivered.

What does the review example actually check?

It states that the primary endpoint matches, every analysis population adds up, a clean rerun reproduces the results, and all eleven references were found one by one.

Is a perfect match required?

No. The deliverable described for reproduced results is a comparison report, figures and code, with notes on differences. Documenting a difference is part of the job.

What file sizes and formats does a project accept?

Excel, CSV, Word, PDF and zip files up to five gigabytes in total. Export Wind or CNKI data first.

Does the tool promise a journal will accept the reproduction?

No. It describes a plan-first workflow, a second check, and specific deliverables. Editorial decisions are outside any tool.
