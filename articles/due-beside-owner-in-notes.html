Write a due date beside every named owner in the notes

Charles Li / HumanPen

An owner without a due date is still an open loop. In the notes, write a due date beside every named owner—not only beside the action—so follow-ups aren’t open-ended. After a flag review, do the same for rewrite and escalate owners.

This is distinct from label-owner-on-each-action, from confirm-owner-before-leave, from end-with-owners-readback, from schedule-followup-before-leave, from capture-decision-in-chat, and from timebox-agenda-then-open. Here the literacy move is concrete: owner + due on the same note line.

This note is detector-report literacy. It does not promise any score, and it is not a detection-evasion guide.

Better order

  1. For each action, write: action · [Owner] · due YYYY-MM-DD (or “Fri EOD”).
  2. Example: “Rewrite §3 flagged spans · [Maya] · due 2026-10-17” · “Escalate ID mismatch · [Tutor R.] · due Mon office hours.”
  3. If the date is unknown, write “due TBD by [Owner] before [next check]”—never leave a bare name.
  4. On the owners readback, speak the due aloud with the name.
  5. Flag review: rewrite owners and escalate owners each get a due next to the name.

Why bare names stall

Tutors in India and Southeast Asia English-medium programs return to queues and marking. A name alone drifts; a due beside the owner keeps the export rewrite pass on a calendar, not in “sometime.”

What this is not

  • Not a guarantee the next badge will clear.
  • Not pressure for an unrealistic date—pick a real next check-in.
  • Not a substitute for a formal integrity process if one is opened.

Where HumanPen fits

HumanPen at humanpen.net supports document-level revision against a report when your notes already pair rewrite/escalate owners with dues. No guaranteed next percentage.

Remember

  • Due beside every named owner—not just the action.
  • Bare name ≈ open-ended follow-up.
  • Flag review: rewrite and escalate both need dues.
  • Honest tools do not promise a clean next card.
