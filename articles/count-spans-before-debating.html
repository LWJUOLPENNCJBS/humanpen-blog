Count how many spans the report marked before debating one sentence

Charles Li / HumanPen

One awkward sentence fills the whole meeting. Before you argue it, count the marked spans on that attempt. A lone highlight and a page full of bands are different conversations—tunnel vision on one line misses whether the flag is dense or sparse.

This is distinct from coverage-before-percent, from triage-flagged-sentences, from flagged-span-checklist, from quote-span-verbatim-in-notes, from print-span-page-numbers, from read-legend-aloud-before-spans, from one-question-per-meeting, and from paste-export-link-not-badge. Here the literacy move is concrete: span count first, then debate a single line in context.

This note is detector-report literacy. It does not promise any score, and it is not a detection-evasion guide.

Better order

  1. Open the scored export; confirm attempt id.
  2. Count marked spans (or note “about N” if the UI shows a total).
  3. Write that count under the attempt id in your notes.
  4. Then pick one span for your one question—knowing if it is 1 of 3 or 1 of 40.
  5. If density surprises you, ask the tutor about clusters before rewriting plans.

Why the count reframes the talk

Tutors in India and Southeast Asia English-medium programs need scale. Debating a single pale line when the report shows dozens of bands wastes the slot on a non-representative sample. Counting first sets honest scope.

What this is not

  • Not a guarantee the next badge will clear.
  • Not a claim that few spans mean “safe” or many mean “guilty.”
  • Not a substitute for a formal integrity process if one is opened.

Where HumanPen fits

HumanPen at humanpen.net supports document-level revision against a report after you understand how dense or sparse the marks are on that attempt. No guaranteed next percentage.

Remember

  • Count spans before debating one sentence.
  • Dense vs sparse changes the conversation.
  • Tunnel vision on one line misses scale.
  • Honest tools do not promise a clean next card.
