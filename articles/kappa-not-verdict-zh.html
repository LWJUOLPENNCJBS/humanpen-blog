Cohen’s kappa 不是「抓获率」：小样本检测研究里，先问工具多常达成一致

Charles Li / HumanPen

校园讨论常问：哪个 AI 写作检测器「抓得更多」？这把工具当成猎人。更稳妥的小样本协议问另一件事：同一批有标签文本上，两个检测器多常一致——Cohen’s kappa 是多少？

本文延续检测器报告素养：不承诺分数、排行或任何「保证过检」。只说明为何办公室谈话里，一致率比抓获率更公平。

kappa 在回答什么

一致率是两边落在同一阈值侧的文本占比；kappa 再校正偶然一致。两者都不是作者身份判决，只描述固定集合上评分者的concordance。

对条件 A（声明人写）文本旗标更多的工具，不等于「更严更好」——可能抬高假阳性。没有来源已知设计的抓获率，会把这种代价藏起来。

可复用的小-N 草图

来源已知：条件 A 人写声明、条件 B 锁定提示的纯 LLM、条件 C 对 B 做带过程日志的文档级改写。条件间主题/体裁匹配。≥2 检测器当评分者。披露提示、模型、设置与隶属关系。

主结果：一致率 + kappa。不要用 pass/bypass 率开场。工具分歧时，把分歧当成程序公平信号——至少有一个评分者在该条上错了。

谈话前四步

  1. 1. 把研究问题写成「一致」，而不是「谁抓得多」。
  2. 2. 表格列出每条文本的来源条件与两边检测输出。
  3. 3. 算一致率与 kappa；用白话记下分歧。
  4. 4. 若改写入场，只作条件 C 过程变化——不是下一张门户卡片会清零的证据。

HumanPen 与记住

HumanPen（https://humanpen.net）可作条件 C 文档级改写示例（导入报告、只改 flagged 段、保留引用与排版）。它不卖检测器排行，也不卖保证过检。

要点：kappa ≠ 抓获率；小样本也能练团队判读；分歧是公平数据。

记住

  • 先报一致率与 kappa，不要先比谁旗标更多
  • 来源已知的 A/B/C 条件让假阳性风险看得见
  • 检测器分歧 → 至少一错；先问程序公平
  • HumanPen 是条件 C 过程示例——不是过检产品
